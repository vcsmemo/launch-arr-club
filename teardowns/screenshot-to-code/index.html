How Screenshot to Code Makes Money

Screenshot to Code sells convenience to developers who could run the code for free — and it found them by giving the code away first, letting an 81,000-star repository do the marketing while the hosted version charges for not having to set anything up.

1. What problem does it solve?

A screenshot is the fastest spec. A designer hands over a mockup, a founder points at a competitor's page, a developer sketches a layout — and turning that picture into working front-end code used to mean hours of hand-writing HTML and CSS. In November 2023, GPT-4 Vision changed the equation: a model could look at a screenshot and write the code. But using it yourself meant an API key, a Python backend, a JavaScript frontend, and keeping up as models changed.

Screenshot to Code does the whole loop for you. Paste a screenshot, a design mockup, a screen recording or a text prompt, and it returns HTML with Tailwind, React, Vue or Bootstrap — then refine the result with plain-English follow-up prompts. It even renders what it wrote in a headless browser and checks it visually, comparing the output against the screenshot and iterating. Video to Code, added later, does the same from a screen recording, capturing hover states and animations.

2. Who pays, how much, and in what scenario?

The buyer: a developer, indie hacker or designer who needs a UI built fast — a landing page, a pricing page, an onboarding flow — and would rather pay a few dollars than wire up model keys and servers. Not an enterprise design team.

Usage is billed in credits: one credit buys one generation or one edit, and credits reset on the 1st of each month without rolling over. The prices above are from the hosted app's code as captured in February 2024 — the live pricing page renders by script and shows no prices in plain text (checked Nov 20, 2026). The done-for-you packages, from $99, are listed on the live pricing page and are a second, smaller revenue line: human developers for buyers who want the finished code without touching the tool at all.

The scenario that makes someone pay: a screenshot and a deadline. The first paid version, in December 2023, had no accounts at all — just a Stripe payment link selling 100 generations for $15 and a simple ledger on the backend counting them down. Subscriptions with monthly credits followed within three months.

Sanity check (our estimate, not a reported figure): $4,303 MRR ÷ 281 subscriptions ≈ $15.31 per subscription per month — almost exactly the $15 Hobby price, so the paying base is overwhelmingly on the entry plan. And 281 subscriptions against the founder's 258,000 registered users is a 0.11% conversion rate: the free repository is an enormous top of funnel with a very thin paid tail. MRR annualizes to roughly $51,600 a year. Note that the $4,567 earned in the last 30 days is cash in that period, not MRR — the two are different measures, kept distinct throughout.

3. How did it find these people?

Almost entirely through the repository itself. Founder Abi Raja, a New York founder whose company WhimsyWorks also makes Pico, an AI app builder, posted the tool on X on November 15, 2023. The next day it reached the front page of Hacker News — 358 points, 90 comments — and three days later it was first on GitHub trending. By February 2024 he counted about 1,000 page views a day with no outbound marketing. The stars compounded from there: 35,000+ in February 2024, 40,000+ in March, 80,363 by October 14, 2026, and 81,299 when we checked on November 20.

The funnel is the README. Its first line sends readers to the hosted product, and the free version is fully working with the user's own API key — so developers star it, share it, and fork it (9,959 forks), and a fraction of the traffic pays for the version that needs no setup. The founder's own posts did the rest of the marketing: $1,000 in revenue 19 days after release, posted December 4, 2023. Even other tools fed it — the founder of ScreenshotOne, the screenshot service the app calls to capture pages from a URL, said sign-ups jumped because of this tool.

There is no paid acquisition anywhere in the record. The marketing budget was a public repository, a demo, and a Show HN post.

4. Why does it work?

Screenshot to Code's wedge is not the AI — a vision model is a commodity anyone can call, and v0, Lovable, Bolt, ChatGPT and Claude now accept screenshots natively. The wedge is distribution, and timing: the first open-source screenshot-to-code tool on GPT-4 Vision, released nine days after the API preview opened, when it allowed only 100 requests a day. Being first in that window bought the Hacker News front page, the GitHub trending slot, and the stars — and stars are a durable asset. Every model release since has been a reason to come back: GPT-4 Turbo in April 2024, GPT-4o in May, Claude 3.5 Sonnet in June, Gemini 3 in January 2026. The founder tests each new model on his own examples before switching — "models come and go but evals are forever," he wrote in March 2024 — so the hosted version stays better than a self-run copy on an old setup.

Underneath, the cost structure is the point. The founder says the business needs under two hours a week, and his sale message puts the profit margin at 60% over the last 12 months. Free code plus paid convenience, running on top of someone else's API, with a repository doing the marketing: that is a business a single person can hold for three years — and, on October 14, 2026, list for sale at $38,000 because he is starting a full-time job.

5. Could you build it?

The product, yes. The business, not by copying the product.

Replicable: the shape — a vision-model call, a screenshot comparison loop, a credit ledger — is a weekend-to-months build, and the original is MIT-licensed, so the code itself is public. The pricing shape is copyable too: free self-hosted version with your own key, paid hosted version for everyone else.

Not replicable by cloning: the timing. Being the first open-source screenshot-to-code tool on GPT-4 Vision depended on November 2023. Today the feature is bundled into the tools developers already use, and the revenue curve shows it: the average month before October 2025 earned $8,585, against $5,232 a month over the last 12 months, and $4,567 in the last 30 days — a slow fade no source explains. A clone launched now would be competing with v0 and ChatGPT for the same job, without the repository that brings the traffic.

The opening it leaves: the method, not the product. Release a small open-source tool around a model ability the day it ships. Post the demo on X and Show HN the same day. Keep the free version fully working with the user's own key, so developers star and share it. Sell the hosted version from the first weeks, even with only a payment link and a ledger. The abilities still open in that sense are the new ones that need keys and setup to try — video understanding, realtime voice, computer-use agents. There a free repository can still find users, and a hosted version can still charge for convenience.

What we don't know

  • Whether the Stripe total includes Pico revenue. The account belongs to WhimsyWorks, which also sold Pico, and no source says whether any Pico revenue is in the total — which is why this teardown headlines the last-12-months figure, not the all-time one.
  • Churn and retention — the two numbers that decide whether 281 subscriptions is a stable base or a revolving door. Neither has been disclosed.
  • Why revenue faded about 47% from the early monthly average to the last 30 days. No source explains it — competition from bundled tools is the obvious hypothesis, not a verified fact.
  • Whether the GitHub repository transfers with the $38,000 sale. The sale message does not say, and the repository is what brings the traffic.
  • Current live pricing — the pricing page loads by script and shows no text without it, so the $15/$40 plans are from the app's code as captured in February 2024.
  • Whether the founder's April 2024 "$100K ARR" post was Screenshot to Code alone or the whole company including Pico — the post does not name the product, so we do not use it as this product's ARR.
